# CMN018 direct model support

The supplied CMN018 files are Spectre model cards, not a Virtuoso OA library. The application keeps using verified `analogLib` symbols and generates direct Spectre model references. This supports circuit simulation with selected process models, but it does not create foundry symbols, CDF parameters, PCells, or layout verification.

The server administrator must make the model deck and its usage companion readable in the same server directory:

- `cmn018_gp2a_5v_v1d4.scs`
- `cmn018_gp2a_5v_v1d4_usage.scs`

Set optional `cmn018_model_file` in the simulation server's advanced connection settings to the absolute Linux path of the main `.scs` file. The files remain on the licensed server and are never uploaded in a task, embedded in the desktop build, or returned as artifacts. Generic circuits need no CMN018 setting. A CMN018 task with a missing or malformed path fails during remote preflight before Cadence starts. The application checks both files and all selected deck sections, then records their hashes in the existing protected-file audit.

## Supported direct models

| Family | Spectre model names | Parameter mapping |
|---|---|---|
| 1.8 V standard MOS | `nch`, `pch` | NMOS/PMOS D G S B; `w`, `l`, `m` |
| 5 V standard MOS | `nch_5`, `pch_5` | NMOS/PMOS D G S B; `w`, `l`, `m` |
| Medium threshold MOS | `mench`, `mepch`, `mench5`, `mepch5` | NMOS/PMOS D G S B; `w`, `l`, `m` |
| Native NMOS | `nanch`, `nanch5` | NMOS D G S B; `w`, `l`, `m` |
| Bipolar | `npn2/5/10`, `pnp2/5/10`, and their `_5_rpo` variants | BJT C B E; area multiplier |
| Diode | `ndio`, `pdio`, `nwdio`, `ndio_5`, `pdio_5`, `nwdio_5`, `ndio_m`, `pdio_m`, `ndio_5m`, `pdio_5m`, `dnwpsub`, `pwdnw`, `pwdnw_5` | Diode anode/cathode |

`pdk_corner` accepts `tt`, `ss`, or `ff` and defaults to `tt`. The compiler includes only the necessary deck sections, matches the usage file's `redefinedparams=ignore` setting for multi-family circuits, and disables the selected MOS/BJT mismatch flags for deterministic corner runs. MOS width and length are checked against the ranges printed in the provided model card. Invalid model names, polarity mismatches, and out-of-range geometries are rejected during preview. Macros with mismatch, native capacitors, physical resistors, Monte Carlo, and full PDK layout devices are outside this direct-model integration. BJT piecewise teaching theory is restricted to generic models, because those theory parameters are not available from this model-card reference.

Example connection description:

```text
VDD rail 0 DC 1.8
VG gate 0 DC 1
M1 rail gate 0 0 core_n w=10u l=0.18u
.model core_n cmn018 nch
.corner tt
.op
.save I(M1,d) P(M1,region)
```

The equivalent JSON model entry is `{"id":"core_n","type":"cmn018","name":"nch"}`. Set `components[].type` to `nmos` or `pmos` to match the selected model, and set task-level `pdk_corner` when needed. `generic_nmos` is available independently as a teaching MOS1 model and does not need the process deck.

Connection-path checks and generated-netlist tests run locally. Real CMN018 simulation requires testing on a server with licensed Cadence/Spectre access and the actual model files. Check Spectre version compatibility with the 2011 model card and run a small OP/DC case before relying on results.
